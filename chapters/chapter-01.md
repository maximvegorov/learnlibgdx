Разработку игры начнём с небольшого приложения, которое открывает окно и закрашивает его одним цветом. Этот пример позволит проверить рабочую среду и разобраться, где хранится игровой код, как подключается LibGDX и что происходит при запуске.

В этой главе создадим настольный проект на Java. Для него достаточно двух модулей: `core` с общим кодом игры и `lwjgl3` с кодом запуска на компьютере. Графику, управление и игровые объекты будем добавлять в следующих упражнениях.

## Создание проекта и структуры модулей

### Подготовка рабочей среды

Установите JDK 25 и среду разработки с поддержкой Java 25 и Gradle, например IntelliJ IDEA. JDK содержит инструменты для компиляции и запуска Java-программ. Общие рекомендации по выбору среды приведены в [руководстве libGDX по настройке среды](https://libgdx.com/wiki/start/setup).

Откройте терминал и проверьте установку:

```bash
java -version
javac -version
```

Обе команды должны показать версию 25. Если команда не найдена, проверьте установку JDK и переменную `PATH`. При использовании `JAVA_HOME` она должна указывать на каталог JDK, а не на его подкаталог `bin`.

Для первой сборки понадобится доступ к интернету: инструменты сборки и библиотеки будут загружены автоматически.

Для запуска Gradle на JDK 25 требуется Gradle 9.1.0 или новее. Проверьте версию Wrapper в сгенерированном проекте: совместимость указана в [официальной таблице Gradle](https://docs.gradle.org/current/userguide/compatibility.html#java_runtime).

### Генерация проекта

Для создания проекта используем **GDX-Liftoff** — генератор, на который ссылается [официальная инструкция libGDX](https://libgdx.com/wiki/start/project-generation). Он создаёт исходные файлы и настройки сборки для выбранных платформ.

Скачайте JAR-файл со [страницы выпусков GDX-Liftoff](https://github.com/libgdx/gdx-liftoff/releases). В терминале перейдите в каталог загрузки и выполните:

```bash
java -jar gdx-liftoff-VERSION.jar
```

Замените `VERSION` на номер в имени скачанного файла. В генераторе задайте параметры нашего упражнения:

| Параметр | Значение |
| --- | --- |
| Имя проекта | `my-game` |
| Пакет Java | `ru.learnlibgdx.mygame` |
| Главный класс игры | `MyGame` |
| Платформа | Desktop с LWJGL3 |
| Язык | Java |
| Версия Java для проекта | 25 |
| Каталог назначения | `my-game` внутри репозитория |

Оставьте обязательный модуль `core`, выберите настольную платформу LWJGL3 и простой шаблон приложения, например `ApplicationAdapter`, если он доступен в списке. Дополнительные языки, платформы и расширения для этого упражнения не нужны. Для LibGDX выберите стабильную версию, предлагаемую генератором, без суффикса `SNAPSHOT`.

Создайте проект кнопкой генерации. Каталог `my-game` содержит файлы приложения. В следующих главах продолжим работу с этим же проектом. Далее все пути к исходникам и командам сборки приводятся относительно этого каталога.

### Назначение модулей

В сгенерированном проекте найдите следующие элементы. Схема сокращена: генератор может добавить вспомогательные файлы.

```text
my-game/
├── assets/
├── core/
│   ├── build.gradle
│   └── src/main/java/ru/learnlibgdx/mygame/MyGame.java
├── lwjgl3/
│   ├── build.gradle
│   └── src/main/java/ru/learnlibgdx/mygame/lwjgl3/
│       └── Lwjgl3Launcher.java
├── gradle/wrapper/
├── build.gradle
├── settings.gradle
├── gradle.properties
├── gradlew
└── gradlew.bat
```

Если шаблон использует каталог `src` вместо `src/main/java`, работайте с созданным генератором расположением исходников.

В `core` будем писать правила игры, обработку ввода и отрисовку через API LibGDX. Здесь не должны появляться импорты классов настольного запуска из `com.badlogic.gdx.backends.lwjgl3`.

Модуль `lwjgl3` связывает игру с настольной платформой. Его класс `Lwjgl3Launcher` содержит метод `main()`, создаёт конфигурацию окна и передаёт экземпляр `MyGame` объекту `Lwjgl3Application`. Такой платформенный слой называют **бэкендом**. Устройство запуска описано в [документации стартовых классов libGDX](https://libgdx.com/wiki/app/starter-classes-and-configuration).

Зависимость направлена от `lwjgl3` к `core`: настольный модуль использует игру, а игровой код не требует знания о настольном запуске. Позднее другой платформенный модуль сможет использовать тот же `core`.

Каталог `assets` предназначен для ресурсов: изображений, звуков и других файлов игры. Он не является отдельным Java-модулем.

### Файлы сборки

`settings.gradle` определяет состав проекта. Для нашего упражнения в нём должны быть подключены `core` и `lwjgl3`. Соответствующая запись может выглядеть так:

```groovy
include 'core', 'lwjgl3'
```

Корневой `build.gradle` содержит общие настройки, а файлы `build.gradle` внутри модулей — настройки их сборки и зависимостей. В `gradle.properties` генератор хранит свойства проекта, в том числе версии библиотек. Назначение этих файлов показано в [описании структуры проекта libGDX](https://libgdx.com/wiki/start/project-generation).

Скрипты `gradlew` и `gradlew.bat` запускают **Gradle Wrapper**. Он использует версию Gradle, указанную в проекте, и при необходимости скачивает её. Отдельно устанавливать Gradle для этого упражнения не требуется. Файлы Wrapper, включая каталог `gradle/wrapper`, следует сохранять вместе с проектом. Подробнее — в [документации Gradle Wrapper](https://docs.gradle.org/current/userguide/gradle_wrapper.html).

## Зависимости и первый запуск

### Как подключается LibGDX

Зависимость — это библиотека или другой модуль, код которого использует приложение. Gradle получает внешние библиотеки из настроенных репозиториев и подключает их при сборке.

Найдите в сгенерированных файлах следующие зависимости:

| Зависимость | Назначение |
| --- | --- |
| `com.badlogicgames.gdx:gdx` | Основной API LibGDX для игрового кода |
| `project(':core')` | Подключение игрового модуля к настольному |
| `com.badlogicgames.gdx:gdx-backend-lwjgl3` | Настольный бэкенд |
| `com.badlogicgames.gdx:gdx-platform` с классификатором `natives-desktop` | Нативные компоненты LibGDX для настольных платформ |

Например, объявление основной библиотеки может выглядеть так:

```groovy
api "com.badlogicgames.gdx:gdx:$gdxVersion"
```

Здесь `com.badlogicgames.gdx` — группа, `gdx` — имя библиотеки, а `$gdxVersion` — значение свойства с версией. Запись `implementation project(':core')` подключает соседний модуль. Эти строки уже создаёт генератор: повторно добавлять их не нужно.

Нативные компоненты содержат код для конкретных операционных систем. Сохраните настройки таких зависимостей, созданные генератором. Объявления библиотек и классификаторов разобраны в [руководстве по зависимостям libGDX](https://libgdx.com/wiki/articles/dependency-management-with-gradle).

### Открытие проекта и проверка сборки

Откройте в IntelliJ IDEA каталог `my-game` как Gradle-проект. Также можно открыть его корневой `build.gradle` и выбрать открытие в качестве проекта. Дождитесь завершения синхронизации. Для Project SDK и Gradle JVM укажите установленный JDK 25.

В терминале перейдите в каталог приложения из корня репозитория:

```bash
cd my-game
```

На Linux и macOS проверьте Wrapper и выполните сборку:

```bash
./gradlew --version
./gradlew build
```

Если система сообщает `Permission denied` при запуске `gradlew`, сначала выполните `chmod +x gradlew`.

В Windows PowerShell используются команды:

```powershell
.\gradlew.bat --version
.\gradlew.bat build
```

Первая сборка может занять больше времени из-за загрузки Gradle и зависимостей. Сообщение `BUILD SUCCESSFUL` означает, что задачи сборки завершились успешно. Команда `build` сама по себе не открывает окно игры.

### Минимальный игровой класс

Откройте `MyGame.java` в модуле `core` и замените его содержимое следующим кодом:

```java
package ru.learnlibgdx.mygame;

import com.badlogic.gdx.ApplicationAdapter;
import com.badlogic.gdx.Gdx;
import com.badlogic.gdx.graphics.GL20;

public class MyGame extends ApplicationAdapter {
    @Override
    public void render() {
        Gdx.gl.glClearColor(0.10f, 0.15f, 0.25f, 1.0f);
        Gdx.gl.glClear(GL20.GL_COLOR_BUFFER_BIT);
    }
}
```

`ApplicationAdapter` предоставляет пустые реализации методов жизненного цикла приложения. Мы переопределяем только `render()`: LibGDX вызывает его при отрисовке очередного кадра. Собственный цикл `while` для этого не нужен. Другие методы, например `create()` для начальной настройки и `dispose()` для освобождения ресурсов, понадобятся позже. См. [жизненный цикл приложения libGDX](https://libgdx.com/wiki/app/the-life-cycle).

Вызов `glClearColor()` задаёт цвет очистки через красный, зелёный, синий компоненты и альфа-компонент. В нашем примере значения лежат в диапазоне от `0` до `1`. Вызов `glClear()` очищает цветовой буфер этим цветом. Поэтому каждый кадр будет начинаться с тёмно-синего фона.

В сгенерированном `Lwjgl3Launcher` найдите настройки окна и задайте заголовок и размер:

```java
configuration.setTitle("My Game");
configuration.setWindowedMode(800, 600);
```

Используйте имя переменной конфигурации из своего файла, если оно отличается. Остальной код запуска, включая `StartupHelper`, если генератор его добавил, сохраните. Проверьте, что при создании `Lwjgl3Application` передаётся `new MyGame()`. Настройка окна через `Lwjgl3ApplicationConfiguration` показана в [руководстве стартовых классов](https://libgdx.com/wiki/app/starter-classes-and-configuration).

### Запуск окна

Из каталога `my-game` выполните на Linux или macOS:

```bash
./gradlew lwjgl3:run
```

В Windows PowerShell:

```powershell
.\gradlew.bat lwjgl3:run
```

В IntelliJ IDEA эту же задачу можно запустить через окно Gradle: `lwjgl3 → Tasks → application → run`. Такой способ приведён в [официальной инструкции по запуску](https://libgdx.com/wiki/start/import-and-running).

Должно открыться окно размером 800 × 600 с заголовком «My Game» и тёмно-синим фоном. Пока окно открыто, задача `run` продолжает выполняться — это нормально. Закройте окно, чтобы приложение завершилось.

Если запуск не удался, начните с проверки сообщения об ошибке:

| Сообщение или симптом | Что проверить |
| --- | --- |
| `java` или `javac` не найдены | Установку JDK и значение `PATH` |
| Ошибка несовместимой версии Java | JDK, показанный командой Wrapper `--version`, и настройку Gradle JVM в IDE |
| `Could not resolve` или ошибка загрузки | Доступ к указанному в ошибке репозиторию и настройки прокси |
| Задача `lwjgl3:run` не найдена | Текущий каталог и наличие модуля `lwjgl3` в `settings.gradle` |
| При прямом запуске `main()` не найдены ресурсы | Рабочий каталог конфигурации запуска: он должен указывать на `assets` |

Для первого запуска используйте задачу Gradle. Если позже создадите отдельную конфигурацию запуска `main()` на macOS, учитывайте требование LWJGL3 к первому потоку: в зависимости от сгенерированного запуска это обрабатывает `StartupHelper` либо требуется параметр JVM `-XstartOnFirstThread`. Настройки прямого запуска описаны в [документации libGDX](https://libgdx.com/wiki/start/import-and-running).

### Самостоятельная проверка

Измените цвет фона, подставив в `glClearColor()` значения `0.2f, 0.4f, 0.2f, 1.0f`. Закройте приложение и запустите его снова: фон должен стать зелёным. Затем измените размер окна на 960 × 540 в настольном модуле.

После упражнения вы должны уметь найти игровой класс в `core`, настройки окна в `lwjgl3` и зависимости в файлах Gradle, а также объяснить, почему команда `build` собирает проект, а `lwjgl3:run` открывает приложение.
